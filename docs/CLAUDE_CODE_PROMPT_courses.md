# Задача: добавить в квиз второй предмет — «Microeconomics»

У нас уже есть рабочий Telegram Mini App «World Economy Quiz» (Vite + React + TypeScript, `src/engine`, `src/storage`, `src/telegram`, `src/ui`, `src/i18n`, данные в `public/data/questions.json`, скрипт `content:build`). Теперь в нём должно быть **несколько предметов**: мировая экономика и микроэкономика, а позже, возможно, и другие. Всё, что уже умеет приложение (уровни, обычный и хардкор-режим, финал, работа над ошибками, устный экзамен, статистика), должно работать для каждого предмета отдельно.

Сначала прочитай этот файл целиком, потом посмотри текущий код репозитория и `content/courses/microeconomics/questions_preview.md`. Затем предложи короткий план (что меняется в структуре, этапы, риски) и после этого реализуй. **Главный риск — потерять прогресс, который у одногруппников уже накоплен в мировой экономике.** Миграция должна быть безопасной и покрытой тестами.

### Что внутри микроэкономики

- 15 уровней по учебнику Pindyck & Rubinfeld, 354 вопроса (310 single, 34 multi, 10 order), 120 экзаменационных вопросов с тезисами.
- **29 вопросов показывают график** (поле `chart`): цены-потолки, налог, тариф, издержки фирмы, монополия, монопсония, ломаная кривая спроса, Курно, внешние эффекты, выбор потребителя. В вопросах есть ссылки на области графика: «Which areas make up the deadweight loss? → B + C».
- Экзамен оценивается так: теория 30%, математика 25%, графики 25%, применение 20%. Поэтому у экзаменационных вопросов кроме тезисов есть формулы (`formulas`), подсказка «что нарисовать» (`draw`) и иногда эталонный график (`chart`).
- Вопрос 7 — расчётная задача (`problem: true`). В квизе по ней только вопросы на метод, а решение лежит в тезисах устного режима.

## 2. Данные: схема v2

### `public/data/courses.json` — список предметов

```jsonc
{
  "schemaVersion": 2,
  "courses": [
    { "id": "world-economy", "title": "World Economy", "subtitle": "Oral exam · 110 questions",
      "emoji": "🌍", "file": "courses/world-economy.json", "dataAsOf": "2026-11",
      "levels": 13, "questions": 316, "examQuestions": 110 },
    { "id": "microeconomics", "title": "Microeconomics", "subtitle": "Pindyck & Rubinfeld · oral exam · 120 questions",
      "emoji": "📈", "file": "courses/microeconomics.json", "dataAsOf": "2026-11",
      "levels": 15, "questions": 354, "examQuestions": 120 }
  ]
}
```

### `public/data/courses/<id>.json` — один предмет

Всё как в схеме v1, плюс:

```jsonc
{
  "schemaVersion": 2,
  "course": {
    "id": "microeconomics", "title": "Microeconomics", "subtitle": "...", "emoji": "📈",
    "answerFramework": [            // пустой массив у мировой экономики
      { "kind": "theory", "weight": 30, "label": "Theory", "hint": "Define the concept precisely..." },
      { "kind": "math",   "weight": 25, "label": "Math",   "hint": "..." },
      { "kind": "graph",  "weight": 25, "label": "Graph",  "hint": "..." },
      { "kind": "policy", "weight": 20, "label": "Application", "hint": "..." }
    ]
  },
  "charts": [ /* см. ниже; у мировой экономики пустой массив */ ],
  "questions": [{ /* ...как раньше... */ "chart": "monopoly" /* или null */ }],
  "examQuestions": [{
    /* ...как раньше: n, title, originalTitle, level, keyPoints, quizQuestionIds... */
    "formulas": ["L = (P − MC)/P = −1/Ed"],   // 0–4 строки, обычный Unicode-текст
    "draw": "Demand, MR, MC with Pm, Qm...",  // что нарисовать на листке, или null
    "chart": "monopoly",                       // эталонный график, или null
    "problem": false                           // true = расчётная задача
  }]
}
```

- **ID вопросов уникальны только внутри предмета** (`L01-001` есть в обоих). Поэтому везде — в прогрессе, списке ошибок, кнопке «Сообщить об ошибке» — вопрос адресуется парой `(courseId, questionId)`.
- Валидацию при загрузке (zod или ручная) обнови под v2. Оба файла должны её проходить. Битый файл одного предмета не должен ломать другой: показываем ошибку в карточке предмета.
- `courses.json` грузится при старте, файл предмета — лениво при открытии предмета (микроэкономика весит около 480 КБ без сжатия). На время загрузки — рисованный скелетон.

### Схема графика (`charts[]`)

```jsonc
{
  "id": "ceiling",
  "title": "Price ceiling in a competitive market",
  "x": { "label": "Quantity", "max": 10 },        // оси всегда от 0 до max, математические координаты, y вверх
  "y": { "label": "Price", "max": 10 },
  "curves":  [{ "label": "D", "points": [[0,10],[10,0]], "labelAt": [9.5,1.2], "style": "solid" }],  // style: solid | dashed | bold; label может быть ""
  "guides":  [{ "points": [[0,5],[5,5]] }],        // тонкие пунктирные линии к осям, без подписи
  "ticks":   { "x": [{ "at": 3, "label": "Q₁" }], "y": [{ "at": 5, "label": "P₀" }] },
  "markers": [{ "at": [5,5], "label": "E" }],      // точка с подписью
  "areas":   [{ "label": "B", "polygon": [[3,5],[3,7],[5,5]], "labelAt": [3.6,5.7] }],  // заштрихованные области с буквой
  "texts":   [{ "at": [5,2.4], "text": "shortage" }],
  "notes":   ["Ceiling Pmax below P₀: ..."]        // подпись под графиком
}
```

Буквы областей совпадают с рисунками в учебнике Pindyck, так что студенты узнают их.

## 3. Несколько предметов в интерфейсе

- **Выбор предмета.** При первом запуске — экран «Предметы»: карточки (эмодзи, название, подзаголовок, прогресс: звёзды и пройденные уровни, «Ошибок: N»). Дальше приложение сразу открывает последний выбранный предмет, а в шапке главного экрана есть переключатель «📈 Microeconomics ▾». Если предмет всего один, экран выбора не показывай.
- **Всё остальное работает внутри выбранного предмета:** уровни, брифинг, финал, работа над ошибками, устный экзамен, статистика. Ничего не захардкожено под 13 уровней или 110 вопросов: число уровней, вопросов на финал (`questionsPerLevel × уровни`, у микроэкономики 45) и диапазоны вопросов берутся из данных.
- **Навигация:** добавь предмет в маршрут (например, `#/c/microeconomics/level/7`), чтобы `BackButton` и ссылки работали предсказуемо. Используй hash-роутинг, потому что сайт лежит на GitHub Pages.
- **Кнопка «Сообщить об ошибке»** добавляет в шаблон `courseId`.
- **Статистика** — по каждому предмету отдельно плюс общий итог на экране «Предметы».
- **Настройки** (язык, тема, таймер) — общие. «Сбросить прогресс» — с выбором: этот предмет или всё (с подтверждением). В «О приложении» — `dataAsOf` каждого предмета.
- **Подписи кнопок ответа.** В вопросах с графиком области подписаны буквами A–D, поэтому кнопки там нумеруй цифрами 1–4, а не буквами. Иначе «B + C» на кнопке «A» запутает. В остальных вопросах можно оставить как есть.

## 4. Прогресс: хранение и миграция

- Новая схема `progress_v2`, разложенная по ключам с пространством имён предмета, например: `p2:settings`, `p2:lastCourse`, `p2:<courseId>:levels`, `p2:<courseId>:mistakes`, `p2:<courseId>:oral`, `p2:<courseId>:stats`. Формат значений — компактный.
- **Лимиты CloudStorage** (сверься с https://core.telegram.org/bots/webapps — на момент написания: ключ до 128 символов, значение до 4096 символов, до 1024 ключей на пользователя). Список ошибок по 354 вопросам может не влезть в одно значение. Поэтому в адаптере хранилища сделай общий механизм разбиения на части (`key#0`, `key#1`, … + счётчик частей) и прозрачную сборку при чтении. Запись — с debounce, как сейчас.
- **Миграция v1 → v2.** Посмотри, какие ключи пишет текущий код (вероятно, `progress_v1`). При первом запуске новой версии:
  1. прочитай старые данные;
  2. запиши их в пространство `world-economy`;
  3. прочитай записанное обратно и сверь;
  4. только после успешной сверки удали старые ключи и поставь флаг `p2:migrated`.
  Миграция должна быть идемпотентной: повторный запуск ничего не портит, а оборванная на середине завершается при следующем старте. Fallback на `localStorage` работает с теми же ключами.
- Покрой тестами (Vitest, фейковое хранилище): миграцию на реалистичных данных v1, повторный запуск миграции, обрыв между записью и удалением, разбиение и сборку длинных значений.

## 5. Графики (новая функция)

Компонент `<Chart spec={...} />` рисует график из `charts[]` в том же рисованном стиле, что и всё приложение.

- **SVG с `viewBox`.** Переводи математические координаты в пиксели (ось y перевёрнута), оставь поля под подписи осей и делений.
- **rough.js** (если он уже используется; если нет — SVG-фильтр, как у кнопок). Оси и кривые — «карандашом», `bold` толще, `dashed` пунктиром. Области — штриховка (hachure) приглушёнными цветами палитры, у каждой своя. Буква области — крупно, на светлом кружке, чтобы читалась поверх штриховки.
- **Детерминированная «неровность»:** seed от `chart.id`, чтобы график не дрожал при каждом перерендере.
- **Размер:** во всю ширину карточки, на телефоне не выше примерно 45% экрана. Тап по графику открывает его на весь экран.
- **Тёмная тема:** «мел на грифельной доске», цвета штриховки подбери под тёмный фон с нормальным контрастом.
- **Доступность:** `role="img"` и `aria-label` из `title` и `notes`. Текст на графике — не меньше 12 px при ширине 320 px.
- **Шрифты и символы.** В подписях и формулах есть Unicode: `Q₁ P₀ Σ Δ ᵗ P̄ − ≠ ≈ × ÷`. Проверь, что выбранные шрифты (Caveat/Neucha, Nunito) содержат эти глифы. Если нет — добавь fallback-шрифт с ними (например, Noto Sans через `@fontsource`) или рисуй нижние индексы через `<tspan baseline-shift="sub">`. Формулы — обычный текст, KaTeX не нужен.

**Где показывать:**
1. в карточке вопроса над вариантами ответа, если `question.chart` не `null`;
2. на экране обратной связи (тот же график, чтобы сверить объяснение с рисунком);
3. в устном режиме — кнопка «Показать эталонный график», если у экзаменационного вопроса есть `chart`.

Сделай dev-страницу `#/dev/charts` (только в режиме разработки), где отрисованы все 10 графиков в светлой и тёмной теме. По ней удобно проверять, что ничего не наезжает. Сравни с `docs/charts_preview.png`: содержание должно совпадать, стиль — наш рисованный.

## 6. Устный экзамен для микроэкономики

Режим тот же (случайный вопрос → таймер → «Показать тезисы» → самооценка → мини-квиз по `quizQuestionIds`), плюс:

- **На экране с таймером** — 4 рисованные плашки из `course.answerFramework`: «Теория 30% · Математика 25% · График 25% · Применение 20%», с `hint` по нажатию. Если в вопросе есть `draw`, добавь подсказку «✏️ Возьми листок: нарисуй график». У мировой экономики `answerFramework` пустой — плашки не показываются.
- **После «Показать тезисы»** — три блока, пустые скрываются:
  - «Тезисы» — `keyPoints` с чекбоксами;
  - «🧮 Формулы» — `formulas` моноширинным или аккуратным шрифтом;
  - «✏️ Что нарисовать» — `draw` и кнопка «Показать эталонный график».
- **Самооценка.** Кроме тезисов — два переключателя «Написал формулу» и «Нарисовал график», если в вопросе есть `formulas` или `draw`. Итоговая оценка учитывает их.
- **`problem: true`** — бейдж «🧮 Задача». Тезисы в таком вопросе — это ход решения.

## 7. Контент-пайплайн

- `npm run content:build` → `python3 content/tools/build_bank.py --out public/data` (собирает все предметы, `courses.json` и `questions_preview.md` в папке каждого предмета; при любой ошибке валидации завершается с кодом 1).
- `npm run content:charts` → `python3 content/tools/make_charts.py && npm run content:build`.
- В GitHub Actions перед `vite build` запускай `content:build` (на ubuntu-раннере Python есть), чтобы битый контент не уезжал в прод.
- В README опиши, как добавить третий предмет: создать `content/courses/<id>/course.json` и `src/` в том же формате, запустить сборку — предмет появится в приложении сам, без правок кода.

## 8. Критерии готовности

- Прогресс по мировой экономике, накопленный в старой версии, переживает обновление: проверено тестом на реалистичных данных v1 и вручную в браузере.
- Оба предмета открываются. Прогресс, ошибки, статистика устного режима и звёзды у них раздельные.
- Все 29 вопросов с графиками отображаются правильно на ширине 320 px в светлой и тёмной теме. Буквы областей читаются, кнопки ответов в таких вопросах пронумерованы цифрами.
- Финал микроэкономики собирается из 45 вопросов (по 3 из каждого из 15 уровней) без повторов. Тест на это есть.
- `npm run build`, `npm test` и `npm run content:build` проходят без ошибок. Тесты покрывают: миграцию, разбиение длинных значений, загрузку и валидацию обоих файлов предметов, сборку финала для 13 и 15 уровней.
- В мировой экономике ничего не сломалось (пройди уровень, финал, ошибки и устный режим).
- README обновлён: несколько предметов, графики, пайплайн, как добавить предмет, «Вопросы к контенту».
