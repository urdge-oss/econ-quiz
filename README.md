# Econ Quiz — Telegram Mini App

Квиз для подготовки к устным экзаменам по экономике. Несколько предметов, у каждого свои уровни, финальный экзамен, работа над ошибками, тренировка устного ответа и статистика:

| Предмет | Уровни | Вопросы квиза | Экзаменационные вопросы | Особенности |
| --- | --- | --- | --- | --- |
| 🌍 World Economy | 13 | 316 | 110 | 55 вопросов с цифрами, которые надо обновлять раз в год |
| 📈 Microeconomics (Pindyck & Rubinfeld) | 15 | 354 | 120 | 29 вопросов с графиками, формулы и «что нарисовать» в устном режиме |

Приложение работает внутри Telegram (Mini App) и в обычном браузере. Прогресс синхронизируется между устройствами через Telegram CloudStorage.

Вопросы — на английском (экзамены на английском). Интерфейс по умолчанию тоже английский; в настройках его можно переключить на русский или украинский.

## Запуск

Нужен Node.js 20+ (проверено на 22) и Python 3.10+ для сборки контента.

```bash
npm install
npm run dev             # http://localhost:5173
npm test                # юнит-тесты (Vitest): движок, данные обоих предметов, хранилище и миграция, маршруты
npm run build           # проверка TypeScript + сборка в dist/
npm run preview         # посмотреть собранную версию
npm run content:build   # собрать вопросы всех предметов из content/courses в public/data
npm run content:charts  # перегенерировать графики микроэкономики, затем content:build
```

Вне Telegram приложение работает полностью: прогресс хранится в `localStorage`, кнопка «Назад» рисуется в шапке.

В режиме разработки есть страница `#/dev/charts` (http://localhost:5173/#/dev/charts): все графики в ширину карточки на экране 320 px, в светлой и тёмной теме рядом. В собранной версии её нет.

## Несколько предметов

- При первом запуске открывается экран «Предметы»: карточки с эмодзи, названием, звёздами, пройденными уровнями и числом ошибок, внизу общий итог по всем предметам. Дальше приложение сразу открывает последний выбранный предмет; название предмета на главном экране («Microeconomics ▼») ведёт обратно к списку. Если предмет один, список не показывается.
- Всё остальное (уровни, брифинг, финал, ошибки, устный экзамен, статистика) работает внутри предмета. Число уровней, размер финала (`questionsPerLevel × уровни`: 39 и 45) и диапазоны вопросов берутся из данных.
- Маршруты — в hash, потому что GitHub Pages отдаёт один файл: `#/courses`, `#/c/microeconomics`, `#/c/microeconomics/level/7`, `#/c/world-economy/final`, `…/review`, `…/oral`, `…/stats`, `#/settings`. Идущий забег хранится в памяти: если открыть `…/play` после перезагрузки, приложение вернётся на главный экран предмета. Кнопка «Назад» (и Telegram `BackButton`) всегда ведёт на родительский экран, а не по истории.
- Файл предмета грузится лениво, при первом открытии (микроэкономика — около 480 КБ без сжатия); пока он грузится, показывается рисованный скелетон. Если файл битый, ошибка видна на экране предмета (с кнопкой «Попробовать снова») и в его карточке, а другие предметы работают.
- ID вопросов уникальны только внутри предмета (`L01-001` есть в обоих), поэтому прогресс и ошибки хранятся по предметам, а шаблон «Сообщить об ошибке» начинается с `Question microeconomics / L05-012`.
- Настройки (язык, тема, таймер) общие. «Сбросить прогресс» — отдельная кнопка для каждого предмета и «Сбросить все предметы», каждая с подтверждением. В «О приложении» указана дата данных каждого предмета.

## Как добавить или исправить вопрос

1. Откройте нужный файл в `content/courses/<id>/src/`. Формат вопросов (`bank_part*.md`):

   ```
   @level 5 | slug | Title | Subtitle | 36-44          заголовок уровня и его экзаменационные вопросы
   @brief Факт для брифинга перед уровнем
   ### single | 38,40 | 2 | v chart=monopoly       тип | номера экз. вопросов | сложность 1–3 | флаги
   Q: Текст вопроса
   * правильный вариант             (single: 4 варианта, ровно 1 правильный; multi: 5 вариантов, 2–4 правильных)
   - неправильный вариант
   E: Объяснение, которое видно после ответа
   ```

   Флаги: `v` — цифры устаревают (бейдж «данные на 2026»), `chart=<id>` — показать график из `charts.json`. Для `order` вместо `*`/`-` пишутся пункты `1. … 2. …` **в правильном порядке** (3–6 штук).

   Тезисы устного режима (`exam_points.md`):

   ```
   @exam 7 | Copper demand shift (calculation task) | problem     «problem» = расчётная задача
   - тезис (2–6 штук; у задачи это ход решения)
   = формула (0–4 строки, обычный Unicode-текст)
   > что нарисовать на листке [chart:monopoly]                  необязательно; [chart:…] — эталонный график
   ```

2. Соберите банк: `npm run content:build`. Скрипт проверит исходники (число вариантов, правильных ответов, покрытие экзаменационных вопросов, ссылки на графики, точки графиков внутри осей, дубли) и при ошибке покажет файл и строку и завершится с кодом 1. При успехе он обновит `public/data/` и `questions_preview.md` в папке предмета.

3. Закоммитьте и запушьте — сайт обновится сам. GitHub Actions тоже запускает `content:build`, так что битый контент не уедет в прод.

> ID вопросов (`L05-012`) вычисляются по порядку внутри уровня. Если вставить вопрос в середину уровня, ID следующих сдвинутся, и их счётчики в «работе над ошибками» у игроков перепутаются. Новые вопросы лучше добавлять в конец уровня.

## Как добавить третий предмет

1. Создайте `content/courses/<id>/course.json` по образцу существующих (`id` — латиница, цифры и дефис: он попадает в ключи хранилища; `order` — место в списке; `examQuestionCount`; `finalExam.questionsPerLevel`; `answerFramework` — плашки оценки устного ответа или `[]`).
2. Положите в `content/courses/<id>/src/` файлы `bank_part*.md`, `exam_points.md`, `exam_raw.txt` (и при желании `charts.json`) в том же формате.
3. `npm run content:build`, коммит, пуш. Предмет появится на экране «Предметы» сам, правки кода не нужны.

## Графики

- `content/tools/make_charts.py` описывает 10 графиков микроэкономики как данные и пишет их в `charts.json`: оси от 0 до `max` (y вверх), кривые (`solid`/`dashed`/`bold`), пунктирные направляющие, деления, точки, заштрихованные области с буквами (как в учебнике Pindyck), текст и подписи (`notes`). После правки: `npm run content:charts`.
- `src/ui/Chart.tsx` рисует график в SVG (`viewBox` 270×262): оси и кривые «карандашом» через тот же SVG-фильтр, что у кнопок, с seed от `chart.id` (график не дрожит при перерисовке); области — штриховка своим цветом и углом; буква области — на светлой плашке. Тёмная тема — «мел на грифельной доске». rough.js не используется: его не было в проекте, а фильтр даёт тот же вид без зависимости.
- Размер: во всю ширину карточки, не выше 45% высоты экрана. Тап (или кнопка по фокусу с клавиатуры) открывает график на весь экран, Escape и «Закрыть» — обратно.
- Подписи не наезжают друг на друга: деления, названия осей и буквы областей стоят на месте, а подписи кривых, точек и текст при пересечении сдвигаются вверх или вниз на строку и не выходят за край. У текста есть «ореол» цвета карточки, поэтому он читается поверх линий. На экране 320 px текст на графике не мельче 13 px, нижние индексы — не мельче 12 px.
- Где показывается: в карточке вопроса над вариантами (в таких вопросах варианты пронумерованы 1–4, а не A–D, чтобы «B + C» не путалось с кнопкой «B»); на экране обратной связи вместе с подписью `notes`; в устном режиме по кнопке «Показать эталонный график». Пока вопрос не отвечен, `notes` не показываются, потому что иногда содержат ответ. В `aria-label` они есть всегда.
- Шрифты: Caveat и Nunito не содержат нижних индексов (₀–₉), греческих букв и части математических знаков (≈ ≠ ≥ ∞). На графиках индексы рисуются обычными цифрами со смещением вниз (`<tspan dy>`), так что рукописный шрифт сохраняется. В тексте вопросов и формулах недостающие символы берёт системный шрифт из стека (`system-ui`, Segoe UI, Roboto, SF); на Windows, Android, iOS и macOS они есть, отдельный шрифт не добавлялся.

## Устный экзамен для микроэкономики

Режим тот же: случайный вопрос → таймер → «Показать тезисы» → самооценка → мини-квиз по теме. Дополнительно, если у предмета есть `answerFramework`:

- над таймером — плашки «Theory 30% · Math 25% · Graph 25% · Application 20%», по нажатию — подсказка; если у вопроса есть `draw` — «✏️ Возьми листок: нарисуй график»;
- после «Показать тезисы» — блоки «Тезисы» (у задачи — «Ход решения»), «🧮 Формулы», «✏️ Что нарисовать» с кнопкой эталонного графика; пустые блоки скрыты;
- в самооценке кроме тезисов — «Написал формулу» и «Нарисовал график» (если есть формулы или `draw`), они входят в итоговую оценку;
- `problem: true` — бейдж «🧮 Задача».

У мировой экономики `answerFramework` пустой, поэтому там всё как раньше.

## Хранение прогресса и миграция

- Схема v2 разложена по ключам: `p2_settings`, `p2_lastCourse`, `p2_<course>_levels`, `p2_<course>_mistakes`, `p2_<course>_oral`, `p2_<course>_stats`, плюс флаг `p2_migrated`. Двоеточие (`p2:settings`) из ТЗ заменено на `_`: Telegram разрешает в ключах CloudStorage только `A-Z a-z 0-9 _ -` (до 128 символов, значение до 4096 символов, до 1024 ключей).
- Каждое значение — `{"t": время сохранения, "d": данные}`. В CloudStorage и `localStorage` используется одна и та же раскладка: в ключе лежит число частей, текст — в `ключ_0`, `ключ_1`, … по 4000 символов (`#` из ТЗ в ключах запрещён). Сначала пишутся части, потом счётчик, лишние старые части удаляются. Список ошибок по 354 вопросам занимает больше одной части.
- При загрузке для каждого ключа берётся более свежая из двух копий (облако и локальная), а отставшая копия догоняется. Сохраняются только изменившиеся ключи: локально сразу, в облако с задержкой 1,5 с и сразу при сворачивании приложения.
- **Миграция v1 → v2.** Старая версия хранила всё одним JSON в `progress_v1` (в облаке — частями `progress_v1_0…N`). Если при старте эти данные есть, они переносятся в `world-economy` (и в общие настройки), записываются во все хранилища, читаются обратно и сверяются. Только после успешной сверки старые ключи удаляются и ставится `p2_migrated`. Перенос работает по принципу «новее побеждает», поэтому он идемпотентен: повторный запуск ничего не меняет, оборванный на середине завершается при следующем старте, а прогресс, набранный после обрыва, не затирается. Если хранилище не удалось прочитать или записать, старые ключи остаются до следующего запуска, а игрок всё равно видит свой прогресс.
- Тесты (`src/storage/storage.test.ts`, фейковое хранилище с лимитами Telegram): перенос реалистичных данных v1, выбор более свежей из двух копий v1, повторный запуск, обрыв между записью и удалением, сбой записи в облако, перенос из одного `localStorage`, разбиение и сборка длинных значений, удаление лишних частей, раздельность предметов.

## Деплой на GitHub Pages

1. Создайте репозиторий на GitHub (например `econ-quiz`) и запушьте туда проект.
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` запускается при каждом пуше в `main`: ставит зависимости, собирает контент (`content:build`), гоняет тесты, собирает и публикует. Через 1–2 минуты сайт будет по адресу `https://<ваш-ник>.github.io/econ-quiz/`.
4. `src/config.ts`: `REPO_URL` — ссылка на репозиторий, `REPORT_CHAT` — ник чата или канала (без `@`), куда игроки присылают ошибки в вопросах.

`vite.config.ts` использует `base: './'` (относительные пути), поэтому `base` не нужно менять при переименовании репозитория.

## Привязка к Telegram-боту

1. **Создать бота.** Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя и ник (должен заканчиваться на `bot`). Токен сохраните в секрете; для этого приложения он не нужен.
2. **Привязать Mini App** — любой из способов (можно оба):
   - `/newapp` в BotFather → выберите бота → название, описание, картинка 640×360 → **Web App URL** = адрес сайта → короткое имя (например `quiz`). Получится ссылка `https://t.me/<бот>/quiz`.
   - Кнопка меню: `/mybots` → ваш бот → **Bot Settings → Menu Button** → адрес сайта и подпись кнопки.
3. **Поделиться с одногруппниками.** Прогресс у каждого свой: он привязан к Telegram-аккаунту и одинаков на телефоне и компьютере.

## Технические заметки и отличия от ТЗ

- **Ключи хранилища**: `p2_…` и `ключ_0`, а не `p2:…` и `ключ#0`, из-за ограничений CloudStorage (см. выше).
- **`p2_migrated`** ставится после успешного переноса, но сигналом к переносу служит наличие старых данных, а не отсутствие флага. Если старая закэшированная версия приложения снова запишет `progress_v1`, эти данные не потеряются, а сольются по времени.
- **После переноса** `p2_lastCourse` не задаётся, поэтому одногруппники один раз увидят экран «Предметы» и узнают про микроэкономику; дальше открывается последний предмет.
- **Название** в шапке браузера и в «О приложении» — «Econ Quiz», раз предметов теперь несколько.
- **Версии Telegram**: каждое API включается, только если клиент его поддерживает (`isVersionAtLeast`): `BackButton`/`HapticFeedback`/`setBackgroundColor` — 6.1, `showConfirm` — 6.2, `CloudStorage` и HEX-цвет в `setHeaderColor` — 6.9, `disableVerticalSwipes` — 7.7.
- **Тема**: по `colorScheme` Telegram, вне Telegram — по `prefers-color-scheme`; собственная «бумажная» палитра, весь текст контрастнее WCAG AA. Атрибут `data-theme` работает и на вложенном блоке (так dev-страница показывает обе темы).
- **`python3`**: на Windows это часто заглушка Microsoft Store, поэтому `scripts/py.mjs` пробует `python3`, `python`, `py`. В `build_bank.py` и `make_charts.py` добавлен `newline="\n"`, чтобы на Windows файлы не менялись из-за CRLF. Содержание вопросов и графиков не тронуто: сборка даёт байт-в-байт те же `courses.json`, `courses/*.json`, `charts.json` и превью, что были в архиве.
- **Удалено**: `content/src/`, `data/questions.json`, `public/data/questions.json`, корневой `questions_preview.md`, `scripts/content-build.mjs`. Постановка этой задачи сохранена в `docs/CLAUDE_CODE_PROMPT_courses.md`.

## Вопросы к контенту

Автоматические проверки ничего не нашли: сборка из `content/courses` проходит без ошибок и совпадает с присланными файлами. Все экзаменационные вопросы обоих предметов покрыты квизом, ссылки `quizQuestionIds` и `chart` верны, точки графиков лежат внутри осей, все 10 графиков используются. В микроэкономике ни один вопрос не упоминает график или области A–D без самого графика, а все области из ответов вида «B + C» есть на своём графике. Фактическую проверку вопросов (316 + 354) я не проводил.

Замечания, которые стоит посмотреть человеку:

- World Economy: во всех 40 multi-вопросах в тексте есть «Select all that apply.», а интерфейс показывает ту же подсказку. В микроэкономике этой фразы нет, там всё чисто.
- World Economy: 55 вопросов помечены `v` (цифры 2025 года). Их нужно обновлять раз в год, а заодно поле `dataAsOf` в `course.json`.
- Microeconomics: индексы вроде `Pmax`, `Pb`, `Ps`, `Qm`, `wc` в данных записаны обычными буквами (не `P_max`), поэтому на графиках они выглядят как «Pmax». Это стиль данных, не ошибка, я не менял.
- Microeconomics: у 10 экзаменационных вопросов нет ни формул, ни «что нарисовать». Возможно, так и задумано (чисто теоретические вопросы).

## Roadmap (следующие версии, сейчас не реализовано)

- Рисовалка в устном режиме: нарисовать график пальцем и сравнить с эталонным.
